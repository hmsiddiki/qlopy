QP_Screen — Admin Screen Detection
==================================

Purpose
-------
Provide a tiny, deterministic way to detect the current admin "screen" so themes/plugins can conditionally enqueue assets or run initialization only where needed. This is optimized for speed (no DB calls, static caching, minimal string ops) and uses the existing admin action system (`add_admin_action` / `do_admin_action`).

Location
--------
- Implementation: `admin/inc/screens.php`
- This README: `admin/inc/SCREEN_README.md`

Concepts
--------
- Screen ID: a short, sanitized string that uniquely identifies the current admin page (e.g. `page_edit`, `category_list`, `media_library`, `sample-qpmeta-plugin`).
- Hooks: The system fires admin-only hooks so you can register callbacks with `add_admin_action()`.

Public helpers
--------------
- `get_admin_screen()` — Returns an array with keys: `id`, `base`, `action`, `params` (cached).
- `current_admin_screen()` — Alias for `get_admin_screen()`.
- `is_screen($id_or_pattern)` — Boolean check. Accepts exact ID, array of IDs, or a simple wildcard pattern with `*`.
- `admin_enqueue_for_screen($screen_id, callable $cb)` — Convenience wrapper that registers an enqueue callback using your admin action system.
- `qp_screen_register_pattern($name, callable $resolver)` — Register a custom resolver for special URL patterns. Resolver signature: `fn(string $script, array $get): ?array`.

Hook names (admin-only)
-----------------------
- `admin_enqueue_{screen_id}` — Fired early (before enqueues) with the screen array.
- `admin_screen_{screen_id}` — Fired for per-screen server-side initialization.

Naming rules (deterministic)
----------------------------
- `index.php?page=dashboard` -> `dashboard`
- `media.php` -> `media_library`
- `posts.php?post_type=page` -> `page_list`
- `posts.php?post_type=page&action=edit&id=107` -> `page_edit`
- `taxonomies.php?taxonomy=category` -> `category_list`
- `taxonomies.php?taxonomy=category&edit=1` -> `category_edit`
- Plugin pages: `index.php?page=sample-qpmeta-plugin` -> `sample-qpmeta-plugin`
- Fallback: `{file}_list` or `{file}_{action}`

Menu mapping
------------
If `register_admin_menu()` (in `includes/admin-menus.php`) is passed an optional `screen_id` parameter, `screens.php` will honor that mapping so pages generated by the menus automatically have the desired screen id.

Usage examples
--------------
1) Conditional enqueue (simple)

```php
if (is_screen('category_edit')) {
    enqueue_admin_script('qp-cat-edit', 'assets/js/qp-cat-edit.js', ['admin-jquery'], time(), true);
}
```

2) Hook-based enqueue (preferred, zero-cost when unused)

```php
add_admin_action('admin_enqueue_category_edit', function($screen){
    enqueue_admin_script('qp-cat-edit', 'assets/js/qp-cat-edit.js', ['admin-jquery'], time(), true);
}, 10, 1);
```

Or using the convenience wrapper:

```php
admin_enqueue_for_screen('category_edit', function($screen){
    enqueue_admin_script('qp-cat-edit', 'assets/js/qp-cat-edit.js', ['admin-jquery'], time(), true);
});
```

3) Register a custom resolver for special URL patterns

```php
qp_screen_register_pattern('my_plugin', function($script, $get){
    if ($script === 'index.php' && !empty($get['page']) && $get['page'] === 'my-plugin-page') {
        return ['id' => 'my_plugin_page', 'base' => 'my_plugin', 'action' => 'view'];
    }
    return null;
});
```

Manual test checklist
---------------------
- Visit `posts.php` -> expect `post_list` (default). Use `get_admin_screen()` in a debug helper or temporarily log to verify.
- Visit `posts.php?post_type=page` -> `page_list`.
- Visit `posts.php?post_type=page&action=edit&id=107` -> `page_edit`.
- Visit `taxonomies.php?taxonomy=category` -> `category_list`.
- Visit `taxonomies.php?taxonomy=category&edit=1` -> `category_edit`.
- Visit `media.php` -> `media_library`.
- Visit `index.php?page=sample-qpmeta-plugin` -> `sample-qpmeta-plugin`.
- Confirm that `add_admin_action('admin_enqueue_{id}', ...)` callbacks only run for expected pages (insert a temporary test script or use browser source to check that script is included only on target screens).

Performance notes
-----------------
- The detection function caches its result (static variable); repeated calls are cheap.
- Avoid registering heavy resolvers; prefer simple `qp_screen_register_pattern()` resolvers.
- Register scripts/styles globally but enqueue them only inside screen-specific callbacks for optimal performance.

Debugging
---------
- To temporarily log the computed screen id, add a small `add_admin_action('admin_screen_{id}', ...)` or use the `admin_debug_log()` helper if enabled.
- Do not leave debug logging enabled in production; turn off after verification.

FAQ
---
Q: How do plugin pages created by `register_admin_menu()` map to screen ids?
A: If you pass `screen_id` to `register_admin_menu()` the mapping is stored and `screens.php` will honor it. Otherwise the system falls back to sanitizing `$_GET['page']` or deriving the id from the php filename.
